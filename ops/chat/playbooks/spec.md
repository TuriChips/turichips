## Playbook: spec work

Spec errors spread to everyone, which is why this runs on Opus. Be exact.

1. Read the issue: a spec question, a block split, or a new chip to specify.
2. Work from the original chip's documentation. Every behaviour gets an exact expected result; every block's inputs and outputs get names and widths.
3. Answer questions by changing the spec, so the answer survives. Changes to an existing spec go through a PR labelled `sai-review`.
4. When the spec is ready, split the work into issues titled `<Name>: <task>` so the dispatcher can hand them out.
5. DONE with refs.
